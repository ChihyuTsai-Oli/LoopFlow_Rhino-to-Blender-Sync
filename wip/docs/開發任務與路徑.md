# LoopFlow R2B 3.0 — 開發任務與路徑

本文件把 3.0 重構拆成可在單一工作時段完成、驗證、提交與推送的單位。契約以 `資料契約.md` 為準；即時狀態只記 `重構進度.md`。

## 執行規則

- **能做就做、需確認再停**（R2B／R2O 共用開發原則）：AI 在已決契約與本檔範圍內直接推進文件、空殼、可自動驗證的實作並提交推送短期分支；僅在下列情況停下來問使用者——改已決 ED／ECO、凍結使用者可見名稱／檔名／package 顯示名、破壞性操作、本機安裝正式 runtime、或與決策明顯衝突無法用「3.0 修正」帶過。
- 一次只改一個 repo；同一時間一台電腦／一個 AI。
- 每項從 `v3-development` 建 `codex/v3-<scope>`（文件波次可暫掛既有決策分支，合入前再整理）。
- **可測＝兩端同批**：同一功能的 Rhino producer 與 Blender consumer 同一任務／同一 PR 範圍交付，不拆成「先做完一端再開另一端」。
- Rhino、Blender Sync、importer fork、Toolkit 四邊界；任務不跨邊界塞無關整理。
- 開發按鈕指向 `wip/src/rhino/entrypoints/`；正式安裝／RC 才用隔離 `%APPDATA%` 與 Blender profile。
- **Blender 測試 add-on**：B01／B04 可先交付 N-Panel 空殼按鈕（對齊 Rhino 入口），再於 C／D 垂直任務接功能；隔離 profile、獨立 package ID。
- `前期規劃/` 當原則；無明顯衝突可在實作微調，衝突先改決策表。
- Importer：從 `import_3dm/import_3dm-0.0.18-windows_x64` **複製**到 `wip/` 再改。
