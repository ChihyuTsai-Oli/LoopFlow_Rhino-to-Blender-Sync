# LoopFlow R2B 3.0 — 工作流程

本文件是 3.0 主操作順序與失敗停點的權威來源。細節模擬與決策過程見 `前期規劃/操作流程模擬_合併.md`；若衝突以本檔與 `資料契約.md` 為準。A01 已對照 2.x 行為；標「3.0 修正」處依已決 ED，不重開決策。

## 操作主線

**Models → Camera → Light**（可獨立重跑單一通道）。

開發時：**Rhino 端與 Blender 端同一通道同批實作**，才能測試。

Blender N 面板：標籤 **LoopFlow**；3D 視窗 bar **Rhino to Blender Sync**；Shader Editor bar **Box Projection**（著色輔助，不進同步）。日後 Toolkit 同一標籤、bar **LoopFlow Toolkit**。

## 使用情境

兩端成對；不要交叉混用（例如不要拿 `RBModels` 的檔去 Import Objects）。

| 情境 | Rhino | Blender | 材質 | 檔 | 行為 |
|---|---|---|---|---|---|
| 主模型 | `RBModels` | **Sync Models**／**Update Models** | **有**（圖層材質，名＝`父::末端`） | `models/R2B.3dm`＋`R2B_blocks.json` | 進 `R2B` 集合；wipe 子樹再建；Block 炸開跟定義圖層；同定義多顆 sidecar 關聯複製。Sync 掛／更新 Principled（底色 `#F2F2F2FF`）；Update 幾何同樣重建，**不覆寫**已有同名材質節點 |
| 選取物件 | `RBObjects` | **Import Objects** | **無**（像 FBX） | `models/R2B_Objects_YYMMDD_HHMMSS.3dm` | Scene 根 Empty `R2B_Objects`；幾何當子物件累加；不進 `R2B`、不建圖層資料夾、不讀 sidecar。Import 開檔案總管（預設 `_LoopFlow_Config/loopflow_R2B/models/`） |
| 相機 | `RBCamera`／`RBCameraPush` | Camera Auto On／Off／Push Once | — | `live/camera.json` | 自動＝視角變就覆蓋；手動＝atomic 推一次 |
| 燈光 | `RBLight`／`RBLightPush` | Light Auto On／Off／Sync Lights | — | `live/light.json` | 只同步 LightLayer 子層 Point 位置 |
| Health | `RBOpen` | Open / Health；Open Docs | — | 設定根（不寫交換檔） | 英文摘要；四顆等寬：Config／live／models／Docs |

## 開案

1. 隔離 2.x／3.0（不同 Blender profile、設定根、package ID）。
2. 開啟**已存檔** `.3dm`（未存檔則發布停）。
3. `RBOpen`：英文對話框四顆等寬按鈕左到右 **Open Config → Open live → Open models → Open Docs**。摘要含設定根路徑、Camera／Light／Models／Objects last-good 時間。未存檔＝擋住（英文訊息）。
4. Blender：Work Folder 指同一層；**Open / Health** 懸停看摘要、左鍵開設定根。**Open Docs**（Rhino 對話框同名按鈕）開 GitHub 文件入口 `docs/README.md`（上英下中，再進各語使用說明）。`config.json` 本批尚未落地（路徑仍由工作檔旁資料夾推導）。

**2.x 對照**：`LiveLink_R2B_Open.py` 僅開 Config／DataFolder／DebugLog，無 Health；設定在 AppData `R2B_Path.txt`。3.0 改專案旁 `_LoopFlow_Config/loopflow_R2B/`。

### Open／Health 兩端 I/O（E02）

| | Rhino | Blender |
|---|---|---|
| 觸發 | `RBOpen` | `open_health`（N 面板 Open / Health） |
| 輸入 | 已存檔 `.3dm` | Work Folder（或已存 `.blend` 所在層） |
| 輸出 | 英文對話框；可開 Config／live／models／Docs | 懸停＝Health 摘要；左鍵只開設定根；**Open Docs** 開 GitHub 入口 |
| 不寫 | 不改來源 `.3dm`；不寫交換檔 | 不寫 Rhino 診斷進 importer |
| 擋 | 未存檔 | 沒有 Work Folder 且未存 `.blend` |

## Models

### 3.0 步驟

1. 以**階層圖層樹**選專案圖層（可捲動；含子層）。
2. 彈出**幾何類別勾選**：顯示 `[數量] 類別名`；**記住上次成功匯出的勾選**（同一 Rhino session）；尚無紀錄時 Point／Curve **預設不勾**，其餘預設勾。勾選 Block／Instance 時**不寫 InstanceReference**：同一定義只炸第一顆進 `R2B.3dm`，其餘寫 `models/R2B_blocks.json`，Blender 關聯複製復位。
3. 依明確物件 ID 處理；隱藏／鎖定物件匯出前暫時顯示解鎖；**禁止 `_SelAll`**。
4. 以 File3dm 寫入 `R2B_pending.3dm` → validate → atomic 成 `models/R2B.3dm`；失敗不碰 last-good。
   - 先輸入**排除標記**（預設 `//`；空白＝不排除）；圖層路徑含此文字者不匯出。
   - 只匯出**選取圖層子樹內、實際有物件的圖層及其祖先**（不再帶入全檔其他圖層）。
   - 圖層名稱／顏色／階層比照作業檔。
   - 物件改為 MaterialFromLayer；材質名＝`父圖層::末端圖層`，顏色＝圖層色。
   - **Block 炸開**：幾何跟定義內各物件的原圖層（對不到才用 Block 插入層），才能對到正確材質。
   - 帶入具名視圖；並把目前作用視角／顯示模式寫入開檔用 `Views`（方便開 `R2B.3dm` 目視）。
   - 寫入後釋放 File3dm；atomic 遇檔案鎖定會重試／copy，失敗則保留 pending。
   - 成功／失敗皆彈窗提醒。
5. 來源文件狀態還原（含 `doc.Modified`）；**不** Open 中間檔、不改作用中文件名。
6. Blender **Update Models**（`update_mats=False`）／**Sync Models**（`True`）；路徑＝作業資料夾 → `…/models/R2B.3dm`；呼叫 Sync **內嵌** import_3dm fork（自動載入 rhino3dm）。
   - Update 與 Sync **幾何語意相同**：先 capture 顯隱／鎖定，再 **wipe `R2B` 子樹**（含 Layers／幾何；**不動** Lighting），依最新 `R2B.3dm` 重建，再依 sidecar 關聯複製 Block，再依**名稱** restore exclude／viewport／render／`hide_select`。
   - 差別只在材質：Sync Models 依 `R2B.3dm` 材質名掛基本 Principled BSDF，Base Color 固定 `#F2F2F2FF`；Update **不覆寫**已有同名材質節點，新幾何仍掛同名槽。
   - 不應再出現 `M3D.001` 這類重複 collection。
7. **Import Objects**（獨立通道）：Rhino `RBObjects` 先選取再匯出 → `models/R2B_Objects_YYMMDD_HHMMSS.3dm`（每次新檔、不覆蓋；選到的 Block **每顆獨立展開**；**不寫材質**）。Blender 按 Import Objects：**彈出檔案總管**（預設 `_LoopFlow_Config/loopflow_R2B/models/`），選哪份 3dm 就匯入哪份；取消不匯入。**累加**到 Scene Collection 最上層，parent Empty 名 `R2B_Objects`（再按一次變 `.001`）；**不**進 `R2B` 集合、不 wipe 舊批次、**不賦材質**（像 FBX 純物件）。
8. 空範圍＝阻擋，不假裝成功。

### 兩端 I/O（A01→C01）

| | Rhino | Blender |
|---|---|---|
| 觸發 | `RBModels`；`RBObjects` | `sync_models`／`update_models`／`import_objects` |
| 輸入 | 已存檔；圖層樹；型別勾選；或目前選取 | 作業資料夾 → `models/R2B.3dm`；Import Objects **選檔**（預設 `_LoopFlow_Config/loopflow_R2B/models/`） |
| 輸出 | `models/R2B.3dm`＋`R2B_blocks.json`（atomic）；選取 → `R2B_Objects_時戳.3dm`（無材質） | Sync／Update：`R2B` 集合＋關聯複製；Import Objects：Scene 根 Empty、無材質 |
| 3.0 | 精準 ID；無 SelAll／無 Open 中間檔；略過 `//`；空＝擋 | Sync package 呼叫既有 importer |

## Camera

### 3.0 步驟

1. 透視視角；工作檔須已存檔。
2. Rhino：`RBCamera`＝開／關自動同步（再按一次關）；`RBCameraPush`＝手動推一次（ED-02）。
3. **手動 Push** atomic 寫入 `_LoopFlow_Config/loopflow_R2B/live/camera.json`（`schema_version=1`）。**自動同步**對齊 2.x：視角一變就直接覆蓋同一檔（不經 pending；姿態未變略過）。
4. Blender：**作業資料夾**＝工作檔同層（或按重新整理自動偵測）；**Camera Auto On／Off／Push Once**；僅 parse＋apply 成功才更新已套用狀態。

### 兩端 I/O（A01→D01）

| | Rhino | Blender |
|---|---|---|
| 觸發 | `RBCamera` toggle；`RBCameraPush` | `camera_auto_on`／`off`／`push`；timer `0.016`s |
| 輸入 | ActiveView CameraLocation／Direction／Up／35mm lens | 作業資料夾 → `…/live/camera.json` |
| 輸出 | 設定根 `live/camera.json`（手動 atomic；自動直接覆蓋） | viewport 位置／鏡頭 |
| State | sticky＋路徑快取；自動同步 **Modified 立刻寫盤**（姿態未變略過） | `r2b3_cam_*` wm keys |
| 3.0 | 手動 atomic；自動熱路徑直接覆蓋；標準 sticky | parse＋apply 成功才記 applied |

## Light

### 3.0 步驟

1. Point 在 LightLayer **子層**（預設 `R2B_LT_Points::燈具名`）；本輪**只同步位置**（附 GUID／type）。父層本身不算合法。
2. 無符合點：手動 Push **不發布**；自動同步若本 session 先前有點，發 `clear=true` 讓 Blender 整組刪 empty／燈／燈具（ED-07）。
3. Rhino：`RBLight`＝開／關自動同步；`RBLightPush`＝手動推一次（ED-02）。自動同步**只**在 LightLayer 子層 Point 增刪／換層／移動時寫檔（刪一般模型不碰 `light.json`）；約 0.2s Idle 合併連續變更。
4. Blender：作業資料夾同 Camera；**Light Auto On／Off／Sync Lights**；無對應模板時不留裸 empty；orphan／clear 刪整組。

### 圖層與 collection 範例

集合用**名稱**比對（`Lighting`／`Lighting Fixtures`／`R2B Lighting Points`），外面可以再包任意父 collection。

**Rhino（來源點）**

| 圖層 | 物件 | 同步？ |
|---|---|---|
| `R2B_LT_Points`（父層） | 不要放 Point | 否 |
| `R2B_LT_Points::Down_Light` | Point | 是；JSON `type`＝`Down_Light` |
| `R2B_LT_Points::Pendant` | Point | 是；JSON `type`＝`Pendant` |

**Blender 模板（同步前自己擺）**

| Collection（父層任意） | 放什麼 | 物件名 | 對應 |
|---|---|---|---|
| `…/Lighting` | Blender Light | `Down_Light`、`Pendant` | 與 Rhino 子層末端同名 |
| `…/Lighting Fixtures` | 燈具模型 | `Down_Light.001`、`Pendant.001` | 同名；`.001` 是 Blender 全檔物件不能重名，程式去掉 `.`＋三位數後再對 |

兩個模板 collection 都會搜（先 Fixtures、再 Lighting）；同名的燈與燈具會一起組到同一個 Point。找不到模板就不留裸 empty。

**同步後**

| Collection | 內容 |
|---|---|
| `R2B Lighting Points` | 每個 Rhino Point 一個 empty；底下掛同名的燈 `INST_*`＋燈具 `INST_*`，位置＝該 Point |

改 `Lighting Fixtures` 裡的燈具模板，組裝出來的實例會一起變（共用網格資料）。亮度／顏色目前也共用；某一盞要不同，須在 Blender 對該實例做 Make Single User。

### 兩端 I/O（A01→D02）

| | Rhino | Blender |
|---|---|---|
| 觸發 | `RBLight` toggle；`RBLightPush`；**僅** LightLayer 子層 Point 的 Add／Delete／Replace／Undelete／換圖層 | `light_auto_on`／`off`／`sync_lights`；timer `0.25`s |
| 輸入 | 全場景 Point，過濾 LightLayer（含子層邊界） | 作業資料夾 → `…/live/light.json` |
| 輸出 | `live/light.json`（手動 atomic；自動直接覆蓋；指紋未變不寫） | 差分：只新增／移動／刪除對應 empty；可刪 orphan |
| 2.x 問題 | **零點仍寫空 `points`** | 空 active_guids → 級聯刪帶 `rhino_guid` 的 empty |
| 3.0 修正 | 空＝不寫檔（ED-07） | 空／無效／不發布 → **不清燈**；保留非 `INST_*` 子物件 |

## Box Projection（Shader Editor）

著色輔助，不進 Models／Camera／Light。不寫 UV。只在 **Cycles** 看最終效果（需開 OSL）；EEVEE／Preview 不要求一致。

1. Render Engine 選 **Cycles**。Add 時會打開 `scene.cycles.shading_system`（OSL）。
2. Shading 工作區，開材質節點樹。圖必須是**磁碟上的檔案**（packed／未存讀不到）。
3. 選 Image Texture，N 面板 **LoopFlow → Box Projection** → **Add Box Projection**。插入一顆 Script 節點；Color 改從 Script 輸出。
4. 同一 N 面板：換圖、Scale XYZ（公尺／張）、Location（世界 XYZ）、Rotation（**度數**）、Blend（0＝接縫較硬）。不必點進節點調參數。
5. 舊版（Mapping＋Box 或 Node Group）請重載後再按一次 Add。Update Models 後已接好的材質應仍在。

## 第二輪

改幾何 → Models；改視角／燈點 → Camera／Light。可只跑變更通道。

## 失敗停點

| 情況 | 行為 |
|---|---|
| 未存檔 | 停止發布（Models／Camera／Light／Open；寫入設定根的通道） |
| Models 失敗／取消／中斷 | 仍在原工作檔；last-good 不動；來源還原 |
| Models 空範圍 | 阻擋，不假裝成功 |
| Light 空層／無符合點 | 不發布；不清 Blender 燈 |
| JSON 半寫／parse 失敗 | consumer 不 apply、不更新已套用狀態 |
| 取消／中斷 | 來源還原；不留半套 pending |

## 不涵蓋（3.0 核心）

Toolkit 擴充、Auto Basic Material、自動升級混用、能量／顏色回寫 Rhino。Box Projection 不做全場景材質清單／法線重建／拿掉 Rhino 端 500 box。Blender add-on 不進 Rhino yak。
